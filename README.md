# Ink Tools · 墨水屏工具箱

墨水屏桌面工具：台历 / 时钟 / 番茄钟 / 待办 / 打卡 / 倒数日，一个 Activity、一块 Canvas 画完。

**65 KB · 0 权限 · 0 依赖 · 不联网**。默认只到分钟、只重绘变化的字符，放着不动几乎不耗电。

### 字号与排版

字号是**整体缩放**：`zoom = 档位 / 1.3`，文字、行高、盒子、导航栏乘同一个系数，
所以 1.3 档就是原始设计稿，往上调等于整页等比放大，层级比例不会走样。

放大后放不下的部分不做「挤」，按优先级处理：

- **界面部件（chrome）封顶 1.5×**：页头标题、日期行、按钮走 `C(dp)`，正文走 `F(dp)`；
  **导航栏单独放宽到 1.9×**（`ChromeMath.navPx`），高度跟文字走（`navH`，上限 15% 屏高），
  所以调字号时底部菜单会明显变大，而不是纹丝不动；
- 台历顶部一行按 `CalHead` 的顺序降级：全日期 + 全名 → 只留「还有 N 天」→ 日期去星期 →
  日期最短 → 置顶另起一行 → 不画；右侧倒数用 13dp 粗体（左侧日期 17dp 粗体），
  `alignBaseline()` 让两者墨迹中心对齐；换行时改为与日期同左边缘，两行才排得齐；
- **时钟盒按真实墨迹居中**（`ClockBox`）：数字基线由 Paint 的 ascent/descent 反算，
  有农历时给农历行让位，没有农历时数字独占整盒；不再用 0.64 这种拍脑袋系数；
- 所有线框按钮的文字走统一入口 `BTN()`：字号 `C(dp)` 且夹在按钮高度的 62% 以内，
  基线按真实墨迹居中——按钮高封顶、文字不封顶曾让 3.1 档文字顶穿上边框；
- 先压缩弹性块（台历时钟盒、番茄倒计时），再按顺序丢模块（本周概览七格 → 概览一行 →
  习惯第二行 → 番茄状态行）；
- 打卡月历放不下时换成「每个习惯一行：本月 N 天 · 连续 M 天」，列不下时写明「其余 N 项见记录页」；
- 番茄页的优先级是 **统计 > 配置网格 > 数字大小**：网格整格放不下时先按缺口收
  「数字下限」和「间距」（`numFloor` / `gapFloor`），收不动才退成一行摘要，
  「专注统计」永远在场（3 行放不下压成 2 行），7 天分钟格只在有富余时出现；
  三键固定钉在导航栏上方，任何档位都不会被裁；
- 页码框只在真有第二页时出现，单页不画（否则会压住表头）。位置规则分两种
  （`pageRowY`）：**只有一页时跟着内容走**，内容短时不留一大片空白；
  **有多页时钉在固定位置**——每页行数不一样（末页可能只剩一行），
  跟着内容走的话翻页键会在两次点击之间跳位置，第二下就点空了。
  电量键值表同理，翻页键钉在表格区底边；
- **放不下的数据一律翻页，不省略**：电量键值表、记录页明细都是分页看全，
  不再出现「已省 N 行」这种「有数据但看不到」的提示；
- **多档选择不循环点击**：能一排放下的（范围、习惯）用**方框分段键**，当前项加内框；
  放不下的（习惯太多）折叠成「更多 ›」，点开才弹窗。循环点击在选项变多之后
  （24 个月归档、十几个习惯）要点十几次才能轮到目标；也让「当前选了什么」在头上就能看见；
- **选月份用系统年月转盘，不用列表**：`DatePickerDialog` 在这台 ROM 上既不肯进
  spinner 模式（`datePickerMode=spinner` 无效），顶部还是一条亮蓝 header，
  墨水屏上不能接受；改用两个系统 `NumberPicker` 拼成「年 / 月」两列，
  手感一样是转盘，但只有黑白，也不会多出「日」那一列；
- **弹窗里的颜色**：应用主题 `InkApp` 继承原来的 `Theme.NoTitleBar.Fullscreen`，
  只把 accent / primary / control 全钉成黑色——老主题里没定义 accent，
  弹窗某些路径会回落成框架默认的蓝色。**遗留**：这台 ROM 的对话框在标题下
  仍有一条 1~2px 的浅蓝分隔线（所有系统弹窗都有，添加待办、确认删除都一样），
  这是 ROM 层面画的，主题覆盖不到；要彻底消掉得把弹窗改成 Canvas 自绘；
- 待办条目连「紧凑行」都放不下时，隐藏「改 / 删」让位给文字——
  3.1 档下宁可少两个小按钮，也不能让列表一个字都不显示；
- 倒数日只有置顶项才做大卡，高度跟字号走（`F(54)`），主数字 `min(内部高度 × 0.86, F(38))`；
  普通条目一律带边框，不再是散落的文字；
- 底部按钮统一规则：单行 ≤4 键的页面（清单 / 打卡 / 番茄 / 倒数）钉在导航栏上方，
  长文流页面（建议）跟随内容；
- 电量统计页统一成「一个主数字 + 一张键值表」：标签左、值右、字号一致，
  数值与单位由纯类 `BattText` 生成，避免同一页里有的字很大有的很小；
  表格被高度裁掉时底部会写明「已省 N 行」，柱状图画不下写「图表略」，不静默丢信息。
- 时钟页倒数与农历 / 电量共用数字下方两行（`ClockStrip`）：用户主动开的倒数优先占第一行，
  第二行放不下就整行隐藏，绝不叠字；点大数字仍可切换农历 / 电量档。

导航栏按「7 个格子中最宽的标签」反算字号上限（测量与绘制都用粗体）；最小触控高度
（`MIN()`）固定不跟着放大，否则 3.1 档下一个按钮会占掉半个屏幕。

### 打卡历史按月归档

打卡位图是**当月** 32 位数组，跨月会被清空——上个月的打卡在磁盘上原本根本不存在。
要能按月回看历史，就得在跨月时把当月位图另存一份（`HabitArchive`），记录页才有东西可显示。

约定与边界：

- **归档只留已结束的月，当前月永远是活的。** 进入新月份时，若归档里已经有这个月
  （系统时间往回拨又拨回来，同一个月被切成两段），那份数据会按位取并集**并回活位图**
  并从归档移除——否则打卡页显示「本月 0 次」而记录页显示这个月有记录，两页自相矛盾。
- **最多保留 24 个月**（2 年）。再多对墨水屏上的翻页没有意义，还会撑大存储。
- 习惯用**稳定 id**（"h1"、"h2"…）而不是名字做键：改名后历史跟着新名字走，
  习惯删掉了历史还在（记录页用归档里的旧名兜底）。
- **跨月之前的记录不会被追溯。** 这套归档从装上这一版之后才开始积累，
  「上月」档在装上这版之前没有数据的月份会是空的——记录页会如实说明这一点。
- 归档随备份一起导出（`"habitArch"` 字段），换机后不该只剩当月。

## 构建

需要 **JDK 17** 与 Android SDK `platforms;android-34`、`build-tools;34.0.0`，不用 Gradle。

JDK 必须用 17：build-tools 34 自带的 d8（R8 8.2.2）处理 JDK 21 编译出的 class 会抛
`NullPointerException`，跟代码无关。`build.sh` 会自己找 17，也可以在 `local.properties` 里指死：

```properties
sdk.dir=D:/Code/Environment/Android/Sdk
jdk17.dir=D:/Code/Environment/Java/jdk-17
```

`local.properties` 与 `debug.keystore` 都在 `.gitignore` 里（前者是每台机器的路径，
后者是签名私钥），所以**新检出 / 换目录后必须自己补这两个文件**，否则构建会在
第一步报「找不到 Android SDK」。

`debug.keystore` 尤其别让它自动生成：设备上已装的包是拿它签的，签名不一致时
`adb install -r` 会报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，只能卸载重装——数据全丢。
`build.sh` 找不到它时会新建一把并打三行警告，看到那三行说明你正踩这条线。

```bash
./build.sh                    # 先跑单测，再出包 eink-toolbox.apk
bash tests/run.sh             # 只跑单测（纯 JVM，不需要设备）
adb install -r eink-toolbox.apk
```

脚本跨平台：自动识别工具后缀（Windows 上是 `aapt2.exe` / `d8.bat`），
没有 `zip` 命令时用 python 写入 `classes.dex`。

### 重构时的截图回归

UI 没有自动化测试，靠「改完拍一遍」太靠人眼。两个脚本组成最小闭环：

```bash
tools/shots.sh  <目录> [标签]     # 依次点 7 个导航格，各截一张
tools/shotcmp.sh <基线目录> <新目录>   # 静态页逐字节比对，台历/时钟/番茄提示人工确认
tools/tap.py shot                # 抓当前屏幕，列出所有文字带及其物理坐标
tools/tap.py tap <x> <y>         # 按物理坐标点击
```

墨水屏无动画、抗锯齿关闭、纯黑白，所以**同一状态的截图是逐字节稳定的**（实测连拍两次 md5 相同）——
清单 / 打卡 / 倒数 / 设置 四页可以用 `cmp` 直接判定「有没有被动过」，重构时这条线比肉眼可靠。
台历、时钟、番茄含实时数字，只提示人工确认。

界面是 Canvas 自绘的，`uiautomator` 拿不到控件节点，定位元素只能靠截图——`tools/tap.py`
把 PNG 解成文字带并给出**物理像素**坐标（注意：图片查看器会把 1448×1072 缩放到 1072 宽，
直接用看图工具上的坐标点会点歪）。

推送 `main` 或打 `v*` tag 时 GitHub Actions 自动打包，版本号是新的会同时发布 Release。

## 电量统计口径

只统计 **App 在前台的时段**，不申请任何权限、不开后台服务：

- **两套时长**：主数字是**未充电使用时长**，键值表另列**含充电总时长**（`BattMath.gross`
  用独立时间戳累计，充电时也照记前台时间）。两者都用 `hero()` 同一精度显示，
  没采到充电时段时写「同未充电」，避免出现「总数比未充电还少」的表观矛盾。
  **掉电与折算一律以未充电时长为分母**，充电时电量在涨，混进来会低估耗电速率。
- **今日**：当天累计使用时长与该时段掉电。中途充过电时保留充电前的掉电，并把起点电量挪到充电后。
- **本次充电后**：从最近一次充电结束起算。
- **近 7 天**：今天 + 最近 6 个归档日桶；柱状图按未充电时长画。
- **全部**：从起算日累计，另给每月、每年折算时长。

充电检测**不依赖 App 正在运行**：电量比上次采样高就判定中间充过电，
所以「插上电充满、期间没打开过 App」也能正确结束上一轮，不会沿用充电前的旧起点。

采样间隔超过 100 秒判定为「离开」，这段时间的时长和掉电都不计入，
只把基点挪到当前——否则离开一晚掉 20%，回来第一分钟会被算成前台消耗。
**1.5 秒以内的同分重绘不计时**（开秒时每秒都会 tick）；系统时间被回拨时不回拨基点，
避免把回拨前的那一分钟算成负时长或重复计入。
